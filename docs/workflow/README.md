# RIFT-SVC 歌曲制作工作流

这套流程用于离线歌曲音色转换与成品制作。目标是先得到稳定、可复现的
RIFT 基准，再通过听感驱动的局部修复、混音和视频封装完成交付。

## 核心原则

- 先建立最简单的可用基准，再记录问题时间点。
- 每次只改变一个主要变量，并保留可直接比较的 AB 试听。
- 分离、音色转换和混音问题分开判断，不用一条复杂链掩盖原因。
- 只修明确有问题的局部，不因几秒瑕疵替换整首人声。
- 分离轨必须独奏确认，不能仅凭 `Vocals` 或 `instrumental` 文件名判断内容。
- 归一化文件只用于辨认素材，正式混音始终使用未归一化原始轨。
- 已确认版本不覆盖；配置、脚本、报告、stem 和成品放在同一版本目录。
- 通用经验写在这里，歌曲专属时间点和参数写在歌曲目录。

## 推荐链路

```text
原始音频
  -> BS-Roformer 124 bands 分离
  -> 选择尽可能干净的主唱轨
  -> RIFT-SVC 基准推理
  -> 与目标伴奏对齐
  -> 局部问题修复
  -> EQ、动态与空间混音
  -> 必要的和声或重放回混
  -> 44.1 kHz / 24-bit 母带
  -> 视频封装与平台验证
```

不默认采用“去和声 -> 去混响 -> RIFT”。连续分离容易损伤咬字、瞬态和
高频；只有确认某个局部确实干扰 RIFT 时，才对该局部增加处理。

## 目录约定

每首歌可以保留现有素材目录命名，但至少应有：

```text
歌曲/演唱者/
├── README.md
├── SOURCES.md
├── ISSUES.md
├── VERSIONS.md
├── 1. RAW/
├── 2. Separation/
├── 3. Auxiliary/
├── 4. RIFT/
├── 5. MIX/
├── 6. Video/
└── 7. ARCHIVE/
```

不要求为了统一命名移动已有大型音频。文档应记录实际路径，并将历史命名差异
视为素材事实，而不是通过大规模重排制造风险。

## 完成条件

- 最终 WAV/FLAC 可解码，采样率、位深、声道和时长符合预期。
- 响度与峰值已测量，局部修复边界无爆音或明显音色跳变。
- 最终版本可由配置和脚本重新生成。
- 歌曲四份文档已更新，废弃版本及原因可追溯。
- 若发布视频，视频流、音轨、首尾解码及平台转码结果均已验证。
